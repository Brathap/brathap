## `> whoami`

I'm **Brathap S**, a systems-focused developer interested in the layer where **software, operating systems, AI, automation and hardware meet**.

I like taking an idea that normally requires several manual steps and turning it into a system that can reason, automate, synchronize and execute those steps itself.

<div align="center">

### `01` — AUTOMATE

> If a process happens repeatedly, it should probably become software.

### `02` — UNDERSTAND

> Don't just use abstractions. Understand what happens underneath them.

### `03` — DESIGN

> Good software is architecture before it is implementation.

### `04` — EXPERIMENT

> Build the weird thing. Learn why it works.

> Complexity should live inside the system, not inside the user's workflow.

<br/>

A recurring design principle in my projects is:

```text
NETWORK AVAILABLE
       ↓
     SYNC

NETWORK LOST
       ↓
    KEEP WORKING
       ↓
LOCAL STORAGE
       ↓
QUEUE CHANGES
       ↓
NETWORK RETURNS
       ↓
     SYNC
```

The application should remain useful even when connectivity disappears.
